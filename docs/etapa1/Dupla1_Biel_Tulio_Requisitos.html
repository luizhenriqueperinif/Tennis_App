Tarefa 1 — Requisitos Funcionais (RFs)

O que é: Um Requisito Funcional descreve algo que o sistema DEVE FAZER. Cada funcionalidade do app vira um RF.

Como escrever: Sempre comece com "O sistema deve..." e separe por ator (Professor / Aluno / Sistema).

💡 Meta Vocês devem ter entre 15 e 25 requisitos no total. Pensem em tudo que o professor e o aluno precisam fazer dentro do app.

RF01ProfessorO sistema deve permitir que o professor crie uma conta com nome, e-mail, telefone e senha
RF02AlunoO sistema deve permitir que o aluno visualize suas aulas do mês em formato de calendário
Agora listem TODOS os requisitos funcionais do app. Pensem em: o que o professor faz? O que o aluno faz? O que o sistema faz automaticamente? Cubram cadastro, aulas, avaliações, partidas, ranking, presença...

Tarefa 2 — Requisitos Não Funcionais (RNFs)

O que é: NÃO são funcionalidades — são qualidades e restrições do sistema. Definem COMO ele deve funcionar (velocidade, segurança, compatibilidade).

Exemplo para entender o formato
IDCategoriaRequisito
RNF01UsabilidadeO sistema deve ser responsivo e funcionar em telas de celular (mobile-first)
Listem pelo menos 4 RNFs. Pensem em: segurança (como as senhas são guardadas?), desempenho (quanto tempo pode demorar para carregar?), compatibilidade (roda em quais navegadores/celulares?), disponibilidade (precisa ficar no ar 24h?).

Tarefa 3 — Regras de Negócio (RNs)

O que é: As regras de negócio são as decisões de produto que definem COMO as funcionalidades se comportam nos detalhes. Não basta dizer "o aluno confirma presença" — a regra define com quantas horas de antecedência, o que acontece se não confirmar, etc.

⚠️ Atenção — Vocês precisam DECIDIR, não apenas listar Cada regra abaixo precisa de uma resposta definitiva. Se ficarem em dúvida, conversem com o Luiz e escolham a opção mais simples para o MVP.
Exemplo para entender o formato
IDRegra de Negócio
RN01O aluno só pode acessar o app se estiver vinculado a pelo menos um professor
Definam as regras do sistema. Para cada pergunta abaixo, escrevam uma RN clara e definitiva.
Perguntas que PRECISAM virar regras escritas:

1. Como o aluno entra no grupo do professor? (código de convite? link? cadastro pelo professor?)
2. O aluno pode pertencer a mais de um professor/grupo ao mesmo tempo?
3. Quem define o nível do aluno? O professor decide manualmente ou o sistema calcula automaticamente por pontuação?
4. Um desafio só pode acontecer entre alunos do mesmo grupo ou pode ser entre grupos diferentes?
5. O resultado de uma partida precisa ser confirmado por ambos os jogadores? E se um contestar?
6. Com quantas horas de antecedência o aluno pode cancelar presença na aula?
7. Tem limite de alunos por aula em grupo? Qual?
8. O ranking é por grupo ou é global (todos os alunos do app)?
9. O ranking zera periodicamente (mensal? semestral?) ou é acumulativo para sempre?
10. Quem pode registrar o placar de uma partida? Só o professor? Os dois jogadores? Qualquer um dos dois?

Tarefa 4 — Histórias de Usuário (User Stories)

O que é: As histórias descrevem funcionalidades do ponto de vista de QUEM VAI USAR. Elas ajudam a entender o PORQUÊ de cada funcionalidade existir.

Formato obrigatório:

"Como [quem sou], eu quero [o que quero fazer] para [por que quero fazer]."

Exemplo
📝 "Como professor, eu quero cadastrar meus alunos pelo app para não precisar anotar em papel."
Escrevam pelo menos 8 histórias (mínimo 4 do professor + 4 do aluno). Cada história deve cobrir uma funcionalidade diferente do app.

Tarefa 5 — Diagrama de Casos de Uso (UML)

O que é: Um diagrama que mostra visualmente QUEM usa o sistema (atores) e O QUE cada um pode fazer (casos de uso).

Como fazer:

  • Usem o draw.io (diagrams.net) — gratuito, roda no navegador
  • Os atores são representados como bonequinhos-palito na lateral
  • Os casos de uso são elipses no centro
  • Linhas conectam cada ator aos casos de uso que ele utiliza
  • Pesquisem "diagrama de casos de uso UML exemplo" no Google Imagens para referência visual
Identifiquem os atores do sistema e listem todos os casos de uso de cada um. Depois desenhem o diagrama no draw.io.
Para montar o diagrama, respondam:
— Quantos atores o sistema tem? (Dica: são pelo menos 2)
— O que cada ator pode fazer? (Olhem os RFs que vocês escreveram na Tarefa 1 — cada RF vira um caso de uso)
— Existe algum caso de uso que AMBOS os atores compartilham? (ex.: fazer login)
