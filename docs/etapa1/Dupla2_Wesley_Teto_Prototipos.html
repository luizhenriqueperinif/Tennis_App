🎯 Seu papel no projeto

Vocês dão "cara" ao app. O time inteiro vai olhar os protótipos para entender como o sistema funciona na prática. Não precisa ser bonito agora — precisa ser claro e navegável. Os protótipos são a ponte entre os requisitos e o código.

📦 Entregável: Protótipo navegável no Figma + link salvo em /docs/prototipos/link-figma.md
⚠️ Dependência importante Vocês PRECISAM dos requisitos funcionais do Biel & Túlio para saber quais telas desenhar e o que colocar em cada uma. Cobrem deles! Enquanto esperam, podem começar pelas telas óbvias: Login, Dashboard e Calendário.

📋 Suas 4 Tarefas

  • 1 Desenhar o Fluxo de Navegação (User Flow)
  • 2 Criar as Telas (Wireframes) no Figma — mínimo 11 telas
  • 3 Tornar o protótipo navegável (links entre telas)
  • 4 Definir a identidade visual básica (cores, fonte, nome)

Tarefa 1 — Fluxo de Navegação (User Flow)

O que é: Um mapa que mostra o caminho que o usuário faz dentro do app — de tela em tela. Pensem nisso como um "GPS" do app.

Como fazer: Peguem um papel, quadro ou o FigJam e desenhem as telas como caixinhas, conectando com setas. Só depois vão para o Figma.

💡 Dica Façam no papel primeiro! É muito mais rápido e vocês podem errar e refazer sem perder tempo. Fotografem o resultado e guardem — serve como documentação.
Exemplo — só para entender o formato

Login → Dashboard ├── Opção A → Tela X → Tela Y ├── Opção B → Tela Z └── Opção C → Tela W → Tela V

Desenhem o fluxo completo para os dois tipos de usuário: Professor e Aluno. Pensem: depois que o professor faz login, o que ele vê? Quais botões ele tem? Onde cada botão leva? Façam o mesmo para o aluno.
Perguntas para guiar vocês:
— O login é o mesmo para professor e aluno, ou são telas separadas?
— Qual é a primeira coisa que o professor quer ver ao abrir o app? E o aluno?
— O aluno que está acessando pela PRIMEIRA VEZ tem um fluxo diferente (inserir código)?
— Quantos "níveis" de profundidade o app tem? (ex.: Dashboard → Lista → Detalhe = 3 níveis)
— O menu fica em cima, embaixo, ou na lateral?

Tarefa 2 — Wireframes no Figma (mínimo 11 telas)

📌 WIREFRAME, não layout final! Nesta etapa, façam telas em preto, branco e cinza. Sem imagens reais, sem cores vibrantes, sem ícones detalhados. A preocupação agora é: o que aparece em cada tela e onde fica posicionado. Beleza vem depois.

Tarefa 3 — Tornar o Protótipo Navegável

O que é: Conectar as telas no Figma para que, ao clicar em um botão, ele leve para a tela certa — como se fosse o app real.

Como fazer no Figma:

  1. Selecione o elemento (botão, card, link)
  2. Vá na aba "Prototype" no painel direito
  3. Arraste o ponto azul até a tela de destino
  4. Escolha a animação (sugestão: "Smart Animate" ou "Slide In")
  5. Clique no botão ▶️ no canto superior direito para testar
Mapeiem quais botões/links levam para quais telas. Façam uma lista antes de sair conectando no Figma.
Para cada tela, perguntem-se:
— Quais elementos nesta tela são "clicáveis"?
— Para onde cada um deles leva?
— O usuário consegue VOLTAR de qualquer tela? (botão de voltar ou menu sempre visível)

Tarefa 4 — Identidade Visual Básica

Mesmo que os wireframes sejam em preto e branco, já deixem anotado para usar nas próximas etapas:

Definam a paleta de cores (2-3 cores principais + 1 cor de erro + 1 cor de fundo), a tipografia (1-2 fontes do Google Fonts) e o nome do app (se já tiverem decidido).
Perguntas para guiar vocês:
— Qual sensação o app precisa transmitir? (esportivo? profissional? divertido? sério?)
— Quais cores vocês associam ao tênis? E à tecnologia?
— Olhem 3-4 apps de esporte que vocês usam (Nike Run Club, Strava, etc.) e anotem as cores que eles usam. O que vocês gostam? O que não gostam?
— A fonte precisa ser legível em tela pequena (celular). Testem no Figma!
— O app tem nome? Se não, proponham 3 opções para o time votar.
