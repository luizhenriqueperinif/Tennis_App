🎯 Seu papel no projeto

Você é o "dono do produto". Não faz o trabalho técnico das duplas, mas é responsável por garantir que elas estão alinhadas, que os entregáveis conversam entre si, e que o projeto não desanda. Se uma dupla trava, é você quem destrava. Se duas entregas se contradizem, é você quem percebe e corrige. Você também é quem monta a apresentação para a FATEC.

🚨 O erro mais comum de um coordenador Achar que é só "delegar e esperar". Se você não cobrar, não alinhar e não validar, vai chegar no final da etapa com 3 entregas que não combinam entre si. O trabalho do coordenador é invisível quando dá certo e muito visível quando dá errado.

Tarefa 1 — Criar o Repositório no GitHub

O que é: O repositório (repo) é onde TODO o projeto vai morar — código, documentos, protótipos, tudo. Centralizar no GitHub garante que ninguém perde arquivo e que todo mundo tem acesso.

Crie o repositório no GitHub e defina a estrutura de pastas. Pense: onde cada dupla vai colocar seus arquivos? Como organizar para que seja fácil de encontrar?
Perguntas para montar a estrutura:
— O repo vai ser público ou privado?
— Quantas pastas principais vocês precisam? (Dica: uma para cada tipo de entregável)
— Onde vai ficar o código quando começarem a programar na Etapa 2?
— Precisa de um README.md explicando o que é o projeto? O que ele deve conter?
— Todos os membros do time já têm conta no GitHub? Todos foram adicionados como colaboradores?

📁 Minha estrutura de pastas:

Desenhe aqui como vai organizar as pastas do repositório...

💡 Dica Pesquise "como criar repositório no GitHub" se nunca fez. É simples: github.com → New Repository → preencha o nome → crie. Depois vá em Settings → Collaborators e adicione o e-mail/username de cada membro.

Tarefa 2 — Montar o Quadro Kanban

O que é: Um quadro visual onde todas as tarefas do time ficam organizadas em colunas que mostram o status de cada uma. Assim todo mundo sabe o que está sendo feito, o que está travado e o que já foi entregue.

Onde criar: Escolha uma ferramenta. Algumas opções gratuitas:

  • GitHub Projects — já fica dentro do repo, integrado
  • Trello — mais visual, fácil de usar
  • Notion — mais completo, mas mais complexo

Estrutura básica do Kanban

📋 A Fazer

tarefas que ainda ninguém começou...

🔨 Fazendo

tarefas em andamento...

👀 Revisão

✅ Feito

entregues e validadas...
Crie o quadro e popule com os cards de tarefas. Cada tarefa de cada dupla vira um card. Atribua responsáveis e prazos.
Perguntas para criar os cards:
— Quantas tarefas o Biel & Túlio têm? Cada uma vira um card?
— E o Wesley & Teto? E o Gabriel Pegador & Du?
— Cada card deve ter: título, responsável(is), prazo e descrição curta
— Quais tarefas DEPENDEM de outras? (ex.: protótipos dependem dos requisitos)
— Vocês vão revisar o quadro em que frequência? (diário? a cada 2 dias?)

Tarefa 3 — Definir o Cronograma da Etapa 1

O que é: Um calendário simples que diz QUANDO cada entrega precisa estar pronta. Sem isso, todo mundo deixa para a última hora.

Monte o cronograma da Etapa 1 definindo datas concretas para cada marco. Lembrem-se que a etapa tem ~2 semanas.
Perguntas para montar o cronograma:
— Qual a data de entrega final da Etapa 1?
— Se a etapa tem 2 semanas, qual é a data limite para cada dupla entregar o rascunho (não a versão final)?
— Quando vai ser a reunião de alinhamento no meio? (Dica: entre os dias 5-7 da etapa)
— Quanto tempo VOCÊ precisa no final para validar tudo e montar a apresentação?
— O que acontece se uma dupla atrasar? Qual o plano B?

Tarefa 4 — Reunião de Alinhamento (meio da etapa)

O que é: Uma reunião rápida (15-20 min) com todo o time para verificar se as 3 frentes estão caminhando na mesma direção. O maior risco em projetos com duplas paralelas é cada um criar algo que não encaixa com o dos outros.

⚠️ Sem essa reunião, o risco é alto Exemplo do que pode dar errado: o Biel & Túlio definem que a aula tem um campo "quadra" nos requisitos, o Wesley & Teto colocam esse campo na tela do Figma, mas o Gabriel Pegador & Du não criaram a coluna "quadra" na tabela do banco. Resultado: retrabalho.
Prepare uma pauta para a reunião. O que você vai perguntar para cada dupla? O que você precisa verificar?
Pauta sugerida — mas adapte com as suas dúvidas reais:

Para Biel & Túlio (Requisitos):
— Quantos RFs vocês já têm? Estão separados por professor e aluno?
— As regras de negócio já foram DECIDIDAS ou ainda são perguntas abertas?
— Tem alguma dúvida que precisa da minha opinião para desempatar?

Para Wesley & Teto (Protótipos):
— Vocês já receberam os requisitos do Biel & Túlio?
— O User Flow está pronto? Posso ver?
— Quantas telas já estão no Figma?

Para Gabriel Pegador & Du (Tecnologia):
— Já definiram a stack? Quais opções estão considerando?
— Começaram o DER? Quantas entidades identificaram?
— Vocês já olharam os requisitos do Biel & Túlio para validar as tabelas?

Verificação cruzada (o mais importante!):
— Os campos que aparecem nos requisitos são os mesmos campos que aparecem nas telas?
— Os campos que aparecem nas telas são os mesmos campos que existem nas tabelas do banco?

Tarefa 6 — Apresentação para a FATEC

O que é: Se a disciplina exigir uma apresentação da Etapa 1, você é responsável por consolidar o trabalho de todo o time em slides claros e objetivos.

Monte a estrutura da apresentação. Quantos slides? O que cada slide mostra? Quem apresenta cada parte?
Estrutura sugerida de slides (adapte conforme a disciplina):

1. Capa — Nome do projeto, nome do time, disciplina
2. O problema — Que dor vocês estão resolvendo?
3. A solução — O que o app faz em 2-3 frases
4. Público-alvo — Para quem é o app?
5. Funcionalidades principais — O que o professor faz? O que o aluno faz?
6. Protótipo — Mostrar 3-4 telas do Figma
7. Tecnologias escolhidas — Stack e banco de dados (com justificativa)
8. Modelo de dados — Mostrar o DER
9. Equipe e divisão — Quem faz o quê
10. Cronograma — As 5 etapas do projeto
11. Próximos passos — O que vem na Etapa 2

Quantos desses slides se aplicam à sua disciplina? Remova o que não faz sentido e adicione o que estiver faltando.

💡 O dia a dia do coordenador durante a Etapa 1

Além das 6 tarefas acima, seu trabalho diário é garantir que ninguém está travado. Aqui vai um guia prático:

O que fazer a cada 2-3 dias

AçãoComo
Checar o Kanban Algum card está parado em "Fazendo" há mais de 3 dias? Se sim, pergunte o que está travando
Perguntar para cada dupla Mensagem rápida no WhatsApp: "E aí, como tá o progresso? Precisa de algo?"
Destravar decisões Se uma dupla está em dúvida sobre alguma regra de negócio, dê sua opinião e bata o martelo. Decisão ruim é melhor que indecisão
Verificar dependências O Wesley & Teto já receberam os requisitos do Biel & Túlio? Se não, cobre!
Reflexão de líder:
— Qual dupla do time tem mais risco de atrasar? Por quê? O que você pode fazer para ajudar?
— Você está cobrando ou está esperando que as coisas aconteçam sozinhas?
— Se uma dupla entregar algo ruim, você consegue dar feedback construtivo sem desmotivar?
— Você sabe o que cada dupla está fazendo AGORA ou só vai descobrir na data de entrega?
